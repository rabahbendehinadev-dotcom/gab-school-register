# الهدف
أريد نظام إشعارات (Web Push) موثوق في مشروع "Registered School".
التثبيت كتطبيق (PWA) جاهز مسبقًا — لا تعمل عليه، ركّز فقط على الإشعارات.
المطلوب: يصلني (كمسؤول/إدارة) إشعار فوري عند كل تسجيل جديد،
ويجب أن يصل الإشعار **حتى والهاتف مقفول أو التطبيق مغلق أو وأنا خارج التطبيق**.

# التقنية المطلوبة
استعمل Web Push API مع مفاتيح VAPID (لا خدمة خارجية مدفوعة).
الوصول للإشعار في الخلفية (والهاتف مقفول/التطبيق مغلق) يتم عبر Service Worker
يستمع لحدث "push" ويعرض الإشعار — هذا هو ما يجعل الإشعار يصل دون فتح التطبيق.

# الخطوات
## 1) مفاتيح VAPID
- ولّد زوج مفاتيح VAPID (public + private) وخزّنهما كـ Secrets/Environment
  (لا تكتبهما في الكود). المفتاح العام فقط يُرسل للواجهة.

## 2) اشتراك جهاز المسؤول في الإشعارات
- زر واضح "تفعيل الإشعارات" يطلب الإذن (Notification.requestPermission)
  عبر ضغطة المستخدم، ثم يشترك عبر pushManager.subscribe بالمفتاح العام VAPID.
- خزّن الاشتراك في قاعدة البيانات (endpoint + keys: p256dh و auth + الدور role=admin).

## 3) Service Worker (هو سر وصول الإشعار في الخلفية)
- عالج حدث "push": اعرض الإشعار بـ showNotification (عنوان + نص + أيقونة + رابط).
- عالج حدث "notificationclick": افتح صفحة تفاصيل التسجيل.
- تأكد أن الإشعارات تُعرض حتى والتطبيق غير مفتوح إطلاقًا.

## 4) الإرسال عند التسجيل (من جهة الخادم)
- بعد نجاح حفظ التسجيل الجديد مباشرة: أرسل Web Push لكل اشتراكات المسؤولين
  بعنوان "تسجيل جديد" ونص يحوي اسم المُسجَّل وأهم التفاصيل + رابط لصفحته.

## 5) موثوقية الإشعارات
- عند فشل 404/410 احذف الاشتراك المنتهي من قاعدة البيانات.
- عند 403 (مفتاح VAPID قديم) أعِد الاشتراك تلقائيًا من الواجهة.
- عالج كل اشتراك على حدة؛ فشل واحد لا يوقف الباقي.

# انتباه خاص بـ iPhone (مهم جدًا)
- على iOS، وصول الإشعار والهاتف مقفول/التطبيق مغلق يعمل **فقط** إذا:
  1) التطبيق مثبّت على الشاشة الرئيسية (وهو جاهز عندك)، و
  2) نظام iOS 16.4 أو أحدث.
- اطلب إذن الإشعارات دائمًا بعد ضغطة زر، لا تلقائيًا.

# معايير القبول
- بعد تفعيل الإشعارات مرة واحدة، عند تسجيل شخص جديد يصل إشعار "تسجيل جديد"
  خلال ثوانٍ **والهاتف مقفول أو التطبيق مغلق تمامًا**.
- الضغط على الإشعار يفتح صفحة تفاصيل ذلك التسجيل.
- اختبر السيناريو الحقيقي: فعّل الإشعارات ← أقفل الهاتف/أغلق التطبيق ←
  سجّل مستخدمًا تجريبيًا ← تأكد من وصول الإشعار على شاشة القفل.

## صوت واهتزاز للإشعار
- عند عرض الإشعار في الـ Service Worker، أضف خيارات:
  { vibrate: [200, 100, 200], silent: false, requireInteraction: true }
  - vibrate: نمط الاهتزاز (يعمل على Android).
  - silent: false: يشغّل صوت الإشعار الافتراضي للنظام.
  - requireInteraction: true: يبقى الإشعار ظاهرًا حتى أضغط عليه (لا يختفي وحده).

# ملاحظة عن iPhone
- على iOS، الصوت والاهتزاز يتحكّم فيهما نظام الهاتف وإعدادات الإشعارات للتطبيق،
  ولا يُدعم نمط vibrate المخصّص كما في Android — يكفي عدم كتم الإشعار (silent: false)
  وسيصدر الصوت/الاهتزاز حسب إعدادات المستخدم.
